# 業務用の公開と運用

## 1. 閲覧と原本の権限を設定する

[デプロイ手順](deploy.md) に沿って、業務用ホストを対象に Cloudflare Access を設定してください。社内 IdP の閲覧グループを使い、アプリごとに異なる AUD を設定します。Worker でも署名・発行元・AUD・期限を確認します。公開前に、未ログインの利用者、別アプリへの権限しか持たない利用者、閲覧が許可された利用者で `/` と `/api/dashboard/30` の両方を確認してください。設定漏れや無効なトークンの場合、Worker は HTTP 403 を返します。

運用者や閲覧範囲が異なるプロジェクトには、R2 バケット、読み取り専用キー、ダッシュボードと Access アプリを分けてください。DuckDB の `--app` はクエリの絞り込みに使います。読み取りキーには原本を保存するバケットだけを許可します。Worker からクエリサーバーにアクセスするトークンは別の値を使います。

## 2. 業務イベントの送信元を制限する

購入や契約確定などのイベント名を `events/projects.ts` の `serverOnlyEvents` に登録します。ブラウザーからの送信は拒否され、古いブラウザー由来のレコードも標準レポートの対象から外れます。原本は保持されます。公開ブラウザー経路のレート制限は Cloudflare 拠点ごとに適用され、初期値はプロジェクト・接続元 IP あたり毎分600リクエストです。

アプリの確定イベントは、アプリ側のトランザクションと一緒にイベント ID・発生時刻・データを保管し、送信失敗時に再送できるようにしてください。デモの Node トラッカーは、そのトランザクションや送信履歴を保持する機能を提供しません。

## 3. R2 から読み込む時間と集計時間を計測する

本番と同等の実行環境と検証用 R2 データで、次のコマンドを実行します。想定規模ごとにファイル構成を変えます。集計期間を変えるだけでは入力ファイルが減らないため、`ANALYTICS_SOURCE` に対象のグロブを設定します。

```sh
pnpm run analytics snapshot --profile --source "$ANALYTICS_SOURCE" \
  --app demo --last-days 180 --output local-data/profiled-snapshot.json
```

CLI が読み込み時間・集計時間・最大常駐メモリ・DuckDB が観測した HTTP リクエスト数を出力します。R2 Metrics で請求対象の操作数を確認します。閲覧経路の応答時間は、検証用ホストでクエリサーバー起動直後の初回とキャッシュに保存された後の両方を測定します。

[Cloudflare R2 のメトリクス](https://developers.cloudflare.com/r2/platform/metrics-analytics/)

## 4. 更新停止と欠損を見つける

画面は最新の集計が取得できないと、取得済みの結果とメッセージを表示します。クエリサーバーの `dashboard_query` と `dashboard_query_failed` のログ、収集 Worker の 4xx・429・5xx、および R2 の保存時刻を確認します。画面の「集計対象の最終受信」は、DuckDB が集計対象とした原本の最新受信時刻です。

`ANALYTICS_MAX_INGEST_LAG_HOURS` を設定すると、受信時刻が許容範囲を超えた場合や対象レコードが空の場合に、クエリサーバーが新しい結果を返しません。週末などの通常の受信間隔を確認してから設定します。

## 5. 再処理と切り戻し

1. クエリサーバーで直近の成功・失敗を確認し、R2 で受信日別の原本を確認します。
2. 原本の欠損がある確定イベントは、アプリの送信履歴から同じ ID・発生時刻で再送します。取り込みが完了してから対象日だけを別ファイルに再集計します。重複は DuckDB がプロジェクト ID とイベント ID で除外します。
3. 対象日の集計を検算します。次のキャッシュ期限後のリクエストで、直近180暦日の集計に修正が反映されます。即時反映する場合はクエリサーバーを再起動し、画面を再取得します。
4. 画面を切り戻す場合は、Cloudflare Workers の Deployments から認証を確認済みの版に戻します。SQL を切り戻す場合は、クエリサーバーで正常な版を起動してください。復旧後に未認証の画面と JSON が保護され、許可された利用者から集計が見えることを確認します。

```sh
pnpm run analytics snapshot --source "$ANALYTICS_SOURCE" --app "$ANALYTICS_APP" \
  --from 2026-11-01 --to 2026-11-02 --tz Asia/Tokyo \
  --observed-until 2026-11-02T00:00:00+09:00 --known-at 2026-11-04T00:00:00+09:00 \
  --output local-data/audit-2026-11-01.json
```

イベント保管期間、業務上必要な個別削除、原本と再送元の保全、CSV 持ち出し、認証鍵の更新時期はデータの管理担当者が決めます。ユーザー単位の削除や送信元の台帳機能はアプリ側の実装と運用手順が必要です。

[Cloudflare Workers の切り戻し](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)。
