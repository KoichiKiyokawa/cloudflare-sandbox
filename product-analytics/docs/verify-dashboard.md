# ダッシュボードを目視で確認する

## サンプルを開く

```sh
pnpm install --frozen-lockfile
pnpm run demo:prepare
pnpm run dashboard
```

`http://127.0.0.1:5173/` を開いてください。サンプルは2026年10月28日から11月26日までの30日間を表示します。

1. 対象プロジェクトが `demo` で、11月26日の DAU が **27**、PV が **36** と表示されることを確認します。
2. 「DAU」と「PV」を切り替えます。グラフ上にポインターを乗せると、日付と値が表示されます。「日別 CSV をダウンロード」で同じ期間の値を取得できます。
3. 「流入元」に切り替え、newsletter、search、community、直接流入の棒を確認します。棒にポインターを乗せると利用者数も表示されます。
4. 「期間」を直近7日・14日・30日・半年（180日）に切り替え、日付の範囲、CSV の行数、流入元の集計が変わることを確認します。
5. DAU と PV のグラフにそれぞれ初期値30・40の目標ラインが表示されます。「目標値」を変更し、入力欄から離れるとラインが移動します。空欄にするとラインが消えます。目標値はプロジェクトと指標ごとに閲覧中のブラウザーに保存されます。

## HTTP キャッシュを確認する

1. ブラウザーの開発ツールでネットワーク記録を開きます。初期表示で `/api/dashboard?days=30` を取得します。
2. 半年を選ぶと `/api/dashboard?days=180` を取得します。その直後に同じ期間を再表示すると、ブラウザーは有効期間内の HTTP キャッシュを使えます。
3. `If-None-Match` にレスポンスの `ETag` を入れて再検証すると、集計結果が同じ場合は HTTP 304 になります。

遅延到着をサンプルで再現するには、`pnpm run demo:prepare --include-late` のあとで開発サーバーを起動し直してください。11月26日の DAU が32、PV が41になります。
